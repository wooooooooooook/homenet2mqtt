# 연결 준비 — 주소·API 활성화를 모르는 사용자와 시작하기

사용자가 H2M을 처음 접했거나, UI만 써 보고 Agent API의 존재·주소·토큰을 모르는 경우가 흔하다. 이 문서는 **추측한 URL로 재시도하는 대신** 설치 형태를 확인하고 주소와 토큰을 만드는 순서를 정리한다.

핵심 구분 하나만 기억하면 된다.

> **UI 주소 ≠ Agent API 주소.** UI는 기본 `3000`(애드온은 ingress), Agent API는 별도 포트(기본 `3001`) 아래 `/api/v1/agent`다. UI 포트에서 `/api/v1/agent/*`를 호출하면 `404`가 난다.

## 1. 먼저 한 번에 묻는다

대화를 여러 번 왕복하면 사용자가 지친다. 아래를 한 메시지로 묶어 묻는다.

1. **설치 형태** — Home Assistant 애드온인가, Docker인가, 직접 실행인가? 애드온이면 이름이 `Homenet2MQTT`인지 `Homenet2Matter`인지
2. **H2M UI가 열리는 주소/방법** — HA 사이드바·애드온의 "웹 UI 열기"인지, `http://<IP>:3000`인지
3. **HA(또는 Docker 호스트)의 IP** — 같은 PC에서 도는지, LAN의 다른 기기인지
4. **UI에 들어가서 `설정 > Agent API` 화면이 보이는지** — 보이면 API 기능은 있는 배포이고, 안 보이면 구버전일 수 있다
5. **Agent API 토큰을 이미 발급받았는지** — 없으면 3절 절차를 안내한다

에이전트가 사용자 PC와 같은 호스트에서 돌고 있다면 1~2번 대신 "H2M이 이 컴퓨터에서 도나요?"만 물어도 된다.

## 2. 설치 형태별로 주소를 만든다

Agent API base URL은 항상 `http://<호스트>:<에이전트포트>/api/v1/agent` 형태다. `https://`는 리버스 프록시로 TLS를 붙인 경우에만 쓴다.

| 설치 형태                            | `<호스트>`                                 | `<에이전트포트>` 결정 위치                                            |
| ------------------------------------ | ------------------------------------------ | --------------------------------------------------------------------- |
| HA 애드온 `Homenet2MQTT` (MQTT)      | HA의 IP (예: `192.168.0.10`)               | 애드온 **구성 → 네트워크**의 `3001/tcp` 매핑. UI에서 변경 불가        |
| HA 애드온 `Homenet2Matter`           | HA의 IP (`host_network` 사용)              | UI **설정 > Agent API**의 "에이전트 API 포트"                         |
| Docker                               | Docker 호스트의 IP (같은 PC면 `127.0.0.1`) | `ports:`에서 publish한 호스트 포트. 기본 예시는 `127.0.0.1:3001:3001` |
| 같은 Docker 네트워크의 다른 컨테이너 | 컨테이너/서비스 이름 (예: `homenet2mqtt`)  | 컨테이너 내부 포트(기본 3001). publish 불필요                         |
| 직접 실행(로컬 프로세스)             | `127.0.0.1`                                | 환경변수가 아니라 UI **설정 > Agent API**에서 저장한 포트(기본 3001)  |

주의할 점:

- HA ingress 주소(애드온의 "웹 UI 열기"로 열리는 주소)는 **UI 전용**이다. 여기에 `/api/v1/agent`를 붙여도 Agent API가 아니다
- 애드온의 `3001/tcp` 네트워크 매핑을 비워 두면 포트가 열리지 않는다. 토글만 켜고 매핑을 안 한 경우가 초보자에게 가장 흔한 실수다
- Docker에서 publish를 `127.0.0.1:3001:3001`로 두면 **호스트 밖에서는 접근할 수 없다.** LAN에서 접근해야 한다면 바인딩을 넓히거나(권장하지 않음) SSH 터널을 쓴다: `ssh -L 3001:127.0.0.1:3001 <user>@<host>` 후 에이전트에서는 `http://127.0.0.1:3001/api/v1/agent`
- 포트가 이미 사용 중이면 서비스가 **최대 9번 다음 포트로 자동 이동**한다. 실제 포트는 UI **설정 > Agent API**의 상태 카드와 기동 로그에 표시된다. Docker라면 컨테이너 안에서 포트가 바뀐 것이므로 `ports:`의 컨테이너 쪽 숫자(예: `3001:3002`)도 함께 맞춰야 한다

## 3. API를 켜고 토큰을 발급한다

Agent API는 **API로 켤 수 없다.** 사용자가 UI에서 해야 한다. 아래를 순서대로 안내하고, 각 단계가 끝났는지 확인한다.

### HA 애드온 `Homenet2MQTT` (MQTT)

1. HA → **설정 > 애드온 > Homenet2MQTT > 구성** 탭에서 **AI 에이전트 API**(`agent_api_enabled`)를 켜고 **저장**
2. 같은 **구성** 화면의 **네트워크** 섹션에서 비활성화된 `3001/tcp` 항목을 눌러 `3001` 입력 → **저장**
3. 애드온 **재시작**
4. 애드온의 **웹 UI 열기** → 처음이면 **AI 에이전트 API 설정** 화면, 이후에는 **설정 > Agent API**에서 **토큰 발급**
5. 표시된 토큰 평문을 **지금 복사** (다시 볼 수 없음)

토글을 끈 채로 UI에 들어가면 "구성 탭에서 켜고 네트워크에서 포트를 지정한 뒤 재시작하라"는 안내가 대신 표시된다. 그 화면에서 억지로 진행하지 말고 1~3을 먼저 끝낸다.

### HA 애드온 `Homenet2Matter`

`host_network`를 쓰므로 포트 매핑이 없다. **구성** 탭에서 `agent_api_enabled`를 켜고 재시작한 뒤, UI **설정 > Agent API**에서 포트와 토큰을 관리한다.

### Docker / 직접 실행

```bash
docker run \
  -e AGENT_API_ENABLED=true \
  -p 127.0.0.1:3000:3000 \
  -p 127.0.0.1:3001:3001 \
  ...
```

UI에 처음 접속하면 비밀번호와 함께 에이전트 API 설정(토큰 자동 생성·포트·패킷 전송 허용)을 입력하는 화면이 나오고, 응답으로 토큰 평문이 한 번 표시된다. 그 이후에는 **설정 > Agent API**에서 재발급·포트 변경을 한다.

### 토큰을 잃어버렸다면

**설정 > Agent API > 토큰 재발급**. 기존 토큰은 즉시 무효가 되므로, 이미 연결해 둔 다른 에이전트가 있다면 함께 갱신해야 한다. `CONFIG_ROOT/agent-api.json`에는 SHA-256 해시만 저장되므로 파일에서 토큰 평문을 복구할 수는 없다.

## 4. 토큰을 에이전트에게 전달하는 방법

- 토큰은 RS485 버스 제어와 설정 파일 수정 권한을 가진다. **채팅·이슈·로그·URL·커밋에 남기지 않는다**
- 사용자가 채팅에 붙여넣어야만 하는 환경이라면, 작업 후 **재발급**으로 무효화하도록 안내한다
- 에이전트 쪽에서는 환경변수 `H2M_TOKEN`으로 받는 것이 기본이다. 셸 히스토리에 남기지 않으려면:

```bash
read -rsp 'Agent API token: ' H2M_TOKEN && export H2M_TOKEN
export H2M_URL="http://127.0.0.1:3001/api/v1/agent"
```

- 스킬 스크립트는 `H2M_TOKEN`이 없으면 즉시 오류로 멈춘다. 토큰 값을 스크립트 파일이나 설정에 하드코딩하지 않는다

## 5. 연결 확인 — 공개 문서 → 인증 호출 순서

토큰 없이도 열리는 문서로 **경로와 포트**를 먼저 확인하고, 그다음 토큰으로 인증 호출을 한다.

```bash
# 1) 토큰 불필요: 주소/포트가 맞는지 (200 + JSON)
curl -sS -o /dev/null -w '%{http_code}\n' "$H2M_URL/openapi.json"

# 2) 토큰 필요: 배포 능력 + 포트 요약
node scripts/h2m.mjs info

# 3) MCP 문도 같은 토큰으로 확인
node scripts/mcp.mjs tools
```

`info`가 포트 목록을 돌려주면 연결은 끝난 것이다. `ports`가 비어 있거나 `setupRequired: true`면 API 문제가 아니라 **설정이 아직 없는 환경**이므로 SKILL.md "신규 환경" 절로 넘어간다.

## 6. 증상별 진단

| 증상                                        | 가능한 원인                                                                                                                   | 다음 행동                                                                   |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `ECONNREFUSED` / `fetch failed` / 연결 거부 | 잘못된 호스트·포트, Docker publish 누락, 방화벽, API 토글 꺼짐                                                                | 2절의 주소 표로 되돌아가 확인. 토글이 꺼져 있으면 포트 자체가 열리지 않는다 |
| 응답 없음(timeout)                          | 다른 VLAN/서브넷, 방화벽, 호스트 IP 오타                                                                                      | 같은 네트워크의 다른 기기에서 `curl`로 교차 확인. 필요하면 SSH 터널 사용    |
| `404`                                       | UI 포트(3000)로 호출, ingress URL에 `/api/v1/agent`를 붙임                                                                    | Agent 전용 포트로 바꾼다. `/api/*`(UI API)로 우회하지 않는다                |
| `401 UNAUTHORIZED`                          | 토큰 오타·공백, 재발급으로 무효화됨, `Bearer ` 접두 누락                                                                      | 토큰 재확인·재발급. 스크립트는 `H2M_TOKEN`만 읽는다                         |
| `503 AGENT_API_DISABLED`                    | 토글은 켰지만 토큰이 없거나(`no_token`), `agent-api.json`을 읽을 수 없음(`store_unavailable`), 또는 토글 꺼짐(`env_disabled`) | 응답의 `reason`을 읽고 UI **설정 > Agent API**에서 토큰 발급 또는 파일 복구 |
| `429 RATE_LIMITED`                          | 분당 120회 초과                                                                                                               | 폴링 간격을 늘린다(`capture wait`는 5초 이상)                               |
| `200`인데 `ports`가 빈 배열                 | 설정이 아직 로드되지 않음(`setupRequired: true`)                                                                              | 연결은 성공. SKILL.md "신규 환경" 절로                                      |

`403`이 나오면 리버스 프록시가 경로나 헤더를 막고 있을 가능성이 크다. 프록시 설정은 API로 바꿀 수 없으므로 사용자에게 확인을 요청한다.

## 7. 하지 말 것

- 포트를 3000~3010으로 **브루트포스**하지 않는다. rate limit과 시간만 소모한다. UI에서 실제 포트를 읽는 것이 먼저다
- UI 세션 쿠키가 필요한 `/api/*`로 우회하지 않는다. 같은 정보는 `/api/v1/agent/*`에 있다
- 토큰을 스킬 폴더·설정 파일·커밋에 저장하지 않는다
- Agent 포트를 인터넷에 그대로 노출하지 않는다. 필요하면 리버스 프록시 + TLS + 접근 제한을 먼저 갖춘다
- 사용자가 이미 쓰는 토큰을 함부로 재발급하지 않는다. 다른 자동화가 함께 끊긴다
